## Plan

plan.md is our living design document: what the game is, what we've decided and why, and
what's next. It always describes the current state of the game. Read it at the start of
every session.

## Working style

- Make one small change at a time, so we can test each one.
- Before a big change, propose the approach and wait for an okay.
- Keep tuning values in @export variables, so we can adjust them in the editor.
- Keep each game object's scene and script together in its own folder.

## Commits

- Commit after each change that works and that we've accepted. Don't commit broken code.
- Each message says why the change was made, not just what changed.
- If a change alters a decision in plan.md, update the plan in the same commit.
- Push at the end of every session.
- Never commit API keys or other secrets.
